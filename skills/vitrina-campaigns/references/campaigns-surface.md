# Campaigns, templates, follow-ups — surface

Connector: every write below is `call_operation {operation_id, params, body}` (`params` = path and query, flat; `body` = JSON). Packs: «Campañas y plantillas» (`campaigns:write`), «Seguimientos» (`followups:write`), «Mensajes a clientes» (`messages:send`). Reads come with the connection. `Unknown operation` = pack missing (add it: Vitrina → Configuración → Conectar tu IA (MCP) → Apps conectadas → «Editar permisos»). Run `describe_operation` before the first call of an id. An `sk_` key sees the same operations plus hand-written tools with the older names noted in parentheses.

## WhatsApp templates (campaigns:read/write)
- `whatsapp_templates_list {messaging_account_id?, status PENDING|APPROVED|REJECTED|IN_APPEAL|PAUSED|DISABLED}` — no limit, includes `param_spec` (large); `whatsapp_template_get`.
- `whatsapp_templates_create {messaging_account_id, name ^[a-z0-9_]+$, language es|es_CL, category MARKETING|UTILITY|AUTHENTICATION, body_text, header_text? | header_media?{format IMAGE|VIDEO|DOCUMENT, url}, footer_text?, buttons?[{type QUICK_REPLY|URL|PHONE_NUMBER|FLOW, text ≤25, …}], param_meta?, usage?}` → 201 PENDING. Header media: `whatsapp_templates_header_media_create {filename, content, content_encoding utf8|base64, content_type}` → `{url, mime_type, size_bytes, format}` (public https url to put in `header_media`; keep one call under ~1 MB over MCP).
- `whatsapp_templates_sync_create {messaging_account_id}` refreshes statuses; `whatsapp_template_update`, `whatsapp_template_delete`, `whatsapp_template_param_binding_update`, `whatsapp_template_param_meta_update`; categories (usage) `whatsapp_templates_categories_list/create`, `whatsapp_templates_category_update/delete` (deleting re-files under `other`), `whatsapp_templates_categories_order_replace`, `whatsapp_template_usage_update`.
- **Excluded for a connector (model spend):** `whatsapp_templates_category_check_create`, `whatsapp_template_infer_bindings_create`. Creating a template still runs both server-side.

## Flows and email templates
- WhatsApp Flows: `whatsapp_flows_list`, `whatsapp_flows_managed_list/get`, `whatsapp_flows_managed_create {messaging_account_id, name, categories[], builder_state? | flow_json?}` (always DRAFT), `whatsapp_flows_managed_update`, `_settings_update`, `_publish_create`, `_deprecate_create`, `_duplicate_create`, `_delete`, `whatsapp_flows_sync_create`. `whatsapp_flows_managed_test_send_create {phone}` sends a real session to that phone (needs «Mensajes a clientes»): name the number first.
- Email templates: `email_templates_list/get`, `email_templates_create {name, design}`, `email_template_update`, `email_template_duplicate_create`, `email_template_delete`. `design` is stored unvalidated: read an existing one before writing.

## Campaigns (campaigns:read/write)
- Read: `campaigns_list {status?, channel?, audience_id?, limit ≤100, offset}` (total in `meta.pagination.total`), `campaign_get {id}` (delivery counters; poll this during a send), `campaign_recipients_list {id, state? pending|sent|delivered|read|failed|suppressed}` (`suppressed` is a success). `sk_`: `campaigns_list {status?, limit ≤50}`, `campaign_stats {campaign_id}`.
- Write: `campaigns_create {name, channel whatsapp|email|voice, audience_id?, messaging_account_id?, template_id?, template_params?{slot:{source contact_field|static, field?, value?, fallback?}} (header_media must be {source:'static', value:<https url>}), content?, reply_mode? account_default|human, scheduled_at?, send_mode? paced|asap, pilot_size?}` (creates a draft; gates run at schedule/send), `campaign_update`, `campaign_delete`, `campaign_pause_create` (stops further delivery only), `campaign_cancel_create`.
- **Reach customers (also «Mensajes a clientes»):** `campaign_test_send_create {recipients[1..5]: phone | email}`, `campaign_schedule_create {scheduled_at}`, `campaign_send_create` (answers `scheduled`, not `sending`: poll `campaign_get`), `campaign_resume_create {send_mode?}`. Readiness gates (audience set, template APPROVED on the same account, verified sending domain for email) return their own 400s.
- Audiences: `audiences_list` (definitions, kind, override sizes), `audience_get`, `audience_counts_list {id, fresh?}` (total, by source, omitted, per-channel reachability), `audiences_stats_list`, `audiences_overlap_list`, `audiences_condition_data_list`; writes `audiences_create {name, description?, filter?, include_contact_ids?, exclude_contact_ids?}` (no filter and no includes = every contact: confirm before pointing a campaign at it), `audience_update`, `audience_delete`, `audience_duplicate_create`, `audience_overrides_create {action include|exclude|reset, contact_ids? | identifiers?}`. **Member listing / preview of people is not published** (health data): use counts.

## Sends that reach customers
- `conversation_messages_create`, `conversation_templates_create {template_id, params?, acknowledge?}`, `conversation_flows_create {flow_id, body, cta, …}`, `conversation_location_create`, `conversation_attachments_create {filename, content, content_encoding utf8|base64, content_type?, caption?, acknowledge?}` (sends a file to the customer; JSON body, keep under ~1 MB over MCP), `conversation_voice_create`, `POST /conversations/email` → `conversations:write` + `messages:send` («Conversaciones» + «Mensajes a clientes»). Macros that reply: `macro_apply_create` (sends straight away, no review) and `macro_run_create {conversation_id, draft_text?, param_values?}` (the reviewed flow: `macro_prepare_list` first) need `macros:read` + `conversations:write` + `messages:send`.
- Customer-notifying acts beyond a plain message: `followups_recontacto_attempt_approve_create`, `followups_subscriptions_create` (future message), `clinic_waitlist_add` (automatic offers), cancelling an appointment (`appointment_cancel_create`, «Agenda» + «Mensajes a clientes»).
- Policy: API keys → loop guard (same content to >20 contacts/10 min or >60 sends/min → 409 `OUTBOUND_WARNING`, repeat with `acknowledge`; 422 `OUTBOUND_BLOCKED`). Connected apps → fan-out rule (>3 distinct contacts/10 min → 202, parked in approvals).
- Approvals (`sk_` tools; the approve/reject screens stay in the UI for connectors): `outbound_approvals_list {rail service_lifecycle|recontacto|seguimiento|campaign|first_touch|api|budget_followup, assignee_user_id?, limit?}`, `_get`, `_approve`, `_reject {id, reason?}`; holds `outbound_holds_list/get/sla_breaches/place/acknowledge/resolve`.

## Follow-ups and recontacto (followups:read/write; «Seguimientos»)
- Rules: `followups_list`, `followups_overview_list`, `followup_get`, `followups_create {name, description, trigger_key, active?}`, `followup_replace`, `followup_active_create`, `followup_delete`, `followups_channels_list` / `followups_channels_replace {whatsapp, email}`. Subscriptions: `followups_subscriptions_list`, `followups_subscriptions_create {followup_id, contact_id, conversation_id?, criteria?, fire_at?, preferred_channel?, fulfiller_kind ai_agent|human_self}` (upsert; an `after_delay` recipe needs `fire_at`), `followups_subscription_cancel_create`, `_renew_create`, `_let_expire_create`, `_fulfill_create`, `followups_subscription_delete`. (`sk_`: `followups_create`, `followups_subscribe`, `followups_subscription_cancel`.)
- Recontacto: `followups_recontacto_list` (config), `followups_recontacto_replace {enabled, daily_cap, lost_lookback_days, max_evaluations_per_step, re_evaluation_after_days, min_hours_between_touches, excluded_template_ids, situations, unanswered_message}` (partial patch; enabling it or a self-sending rung also needs campaigns:write), `followups_recontacto_preview_list`, `_readiness_list`, `_run_create` (forces both sweeps; auto-sends with campaigns:write), `_attempts_list {status?, situation?}` (≤200 rows × ~1.7k chars = 350k — use `_stats_list` for counts and filter by `situation`), `_stats_list {since_days}`, `_attempt_approve_create` / `_attempt_dismiss_create`. Lead reviewer: `followups_lead_review_list` / `followups_lead_review_replace {enabled, stage_autonomy auto|suggest|off, auto_confidence, instructions, half_life_days}`. Demand and template requests: `followups_demand_*`, `followups_template_requests_list`, `followups_template_request_update`.
- **Not available to a connector (model spend / kept interna):** `POST /followups/draft`, the recontacto template draft.

Size traps: `whatsapp_templates_list` (no limit, param_spec), `email_template_get`, `whatsapp_flows_managed_get` (design blobs).
